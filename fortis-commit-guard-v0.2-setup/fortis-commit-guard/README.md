# Fortis Commit Guard — первая устанавливаемая версия

Репозиторий владельца: https://github.com/AlexPastukhh/fortis-commit-guard.

Guard проверяет точный Git commit как данные. Он не запускает код, тесты,
установщики или сборку проверяемого проекта. PASS описывает только выполненные
проверки; разрешение запуска приложения на основной Windows не выдаётся.

## Устройство

| Часть | Назначение |
| --- | --- |
| registry.json | Доверенный реестр проектов, GitHub repository ID и путей профилей |
| profiles/ | Области, допустимые возможности и параметры конкретных проектов |
| checks/security.py | Обязательная проверка структуры, деклараций и отдельных API |
| checks/file_content.py | Общие проверки имён Windows и пассивного содержимого |
| checks/secret_patterns.py | Ограниченный поиск PEM private-key payload и GitHub token prefixes |
| checks/architecture.py | Дополнительная проверка удаления обычных тестов проекта |
| modules.json | Карточки модулей, их гарантии, ограничения и контрольные примеры |
| tests/ | Испытания самих проверяющих инструментов на синтетических Git-объектах |
| .github/workflows/ | Самопроверка guard и ручная проверка коммита проекта |

Сейчас зарегистрирован obs-planning-docs. Общие проверки можно переиспользовать
для других проектов; отдельный guard-репозиторий для каждого не нужен.

## Обязательный security-набор

- Целостность Git-объектов, полный SHA, ancestry от выбранного baseline и лимиты ресурсов.
- Разрешённые области файлов; неизвестные типы и области не получают автоматический PASS.
- Имена и коллизии Windows; запрет симлинков, submodules и executable mode в этом профиле.
- Известные активные HTML-конструкции и interpreter header в пассивных документах.
- Контракт package.json и разрешений userscript; отдельные прямые опасные API и границы импортов.
- Решение владельца при изменении управляющих файлов, AI-инструкций и областей без профиля возможностей.
- Решение владельца при изменении исполняемых .mjs тестов до описания их Node-возможностей.
- Вероятные секреты по ограниченному набору сигнатур; найденные значения не выводятся в отчёт.

Профиль obs-planning-docs и причины ограничений описаны в
[контракте проекта](docs/OBS_PLANNING_DOCS.md).

Все security-модули вызываются независимо от дополнительных проверок.
Параметр architecture может только добавить проверку сохранности обычных тестов.
Если architecture включён в доверенном профиле, параметр false не отключит его.
Поведенческие и дополнительные архитектурные контракты приложения пока отсутствуют.

## Доверие

Чат читает эти правила, но не имеет доступа на запись к их авторитетной версии.
Правила, workflow, профили, baseline и исключения утверждает владелец.
Конфигурация и файлы PASS проверяемого проекта не являются источником допуска.

Производственная проверка запускается в этом guard-репозитории, из main.
Workflow проверки кандидата закреплён за GitHub repository ID 1435231247.
Кандидат получается в свежий bare Git repository без checkout, submodules или
App/PAT credential. Fetch проверяет GitHub ID и публичность источника.
Автоматический GITHUB_TOKEN используется только для чтения собственного guard;
сохранение credential в Git отключено. Доступ к development Docker не требуется.

Рабочие копии, которые агент может изменить, остаются черновиками. Их локальные
JSON-отчёты не являются доказательством допуска. Доверенный потребитель проверяет
источник Actions run, SHA guard, SHA кандидата, hash профиля и статус.

## Результаты

- PASS — перечисленные применимые проверки прошли.
- FAIL — обнаружено нарушение; допуск закрыт.
- REVIEW_REQUIRED — нужен выбор владельца; автоматический допуск закрыт.
- ERROR — проверка не завершилась; допуск закрыт.

Отчёт включает список обязательных модулей и состояние дополнительных проверок.
Полная пофайловая отчётность применимости ещё не реализована.
Отсутствие находок не подтверждает отсутствие любых вредоносных действий.

## Запуск

Нужны Python 3.10+, Git и Node 18+. Acorn включён вместе с MIT license и provenance;
сетевой установки npm-зависимостей нет. Версии сторонних Actions закреплены SHA.

    python3 -m unittest discover -s tests -v
    python3 guard.py --repo /path/to/candidate.git --project obs-planning-docs --candidate FULL_SHA --architecture false --output report.json

Первая загрузка и запуск через GitHub: [INSTALL.md](INSTALL.md).
Изменение правил: [RULE_AUTHORING.md](docs/RULE_AUTHORING.md).

## Что не покрыто

- Полный анализ JavaScript aliases, обфускации и потоков данных.
- Все форматы секретов, произвольные пароли, encoded secrets и dependency vulnerabilities.
- Полный Markdown renderer/sanitizer и безопасность любых текстовых инструкций для ИИ.
- Поведенческая безопасность приложения и сборка Windows-приложений.
- Доверенный импортёр в Windows, автоматический push-посредник и обязательный status check в другом репозитории.

CI после push не отменяет факт появления содержимого на GitHub. Прямой RW-доступ
из development Docker в Windows обходит такую проверку. Эти границы нужно закрыть
отдельно. Настоящие push-credentials должны использоваться вне development Docker.
